# Domain Data API

The operational tables introduced by migrations `0012`-`0021` are exposed through a finite, migration-owned CRUD catalog. They use the authenticated active workspace as the authority boundary; request bodies cannot choose `tenant_id`, `organization_id`, or `workspace_id`.

## Routes

For any catalogued table:

```text
GET    /api/v1/domains/{domain}/{table}?limit=100&offset=0&{field}={value}
POST   /api/v1/domains/{domain}/{table}
GET    /api/v1/domains/{domain}/{table}/{record_id}
PUT    /api/v1/domains/{domain}/{table}/{record_id}
PATCH  /api/v1/domains/{domain}/{table}/{record_id}
DELETE /api/v1/domains/{domain}/{table}/{record_id}
```

`PUT` and `PATCH` apply a partial update. The primary key is generated by the Backend if omitted on create. Tenant, organization, workspace, timestamps, and audit actor fields are Backend-controlled. Unknown fields return `422`; records outside the active workspace return `404`.

List filters are exact-match query parameters. `limit` defaults to 100 and is capped at 200; `offset` defaults to 0. Authority fields cannot be used as client filters.

## Domains And Permissions

- `shared`: `projects`, `tasks`, `work_approvals`, `work_reports`, `work_findings`; permissions `work.read`, `work.write`, `work.delete`.
- `finance`: bank accounts/transactions, receivables/payments, payables/payments, budgets/lines, reconciliations/items, tax obligations/documents, month closes/items; permissions `finance.read`, `finance.write`, `finance.delete`.
- `hr`: employees, attendance, leave, recruitment/candidates/interviews, onboarding, performance reviews, training/enrollments, succession/candidates, grievances, contracts, personnel files; permissions `hr.read`, `hr.write`, `hr.delete`.
- `legal`: permits, contracts, land documents, due diligence/items, cases, claims, expiries, privacy requests, risks, controls; permissions `legal.read`, `legal.write`, `legal.delete`.
- `sales`: customers, leads, opportunities, visits, bookings, closings, follow-ups, complaints, pricing/items, collaterals; permissions `sales.read`, `sales.write`, `sales.delete`.
- `marketing`: campaigns, channels, attributions, contents; permissions `marketing.read`, `marketing.write`, `marketing.delete`.
- `property`: units, milestones, construction packages/updates, inspections/NCRs, safety incidents, change orders, payment certificates, handovers, land pipeline; permissions `property.read`, `property.write`, `property.delete`.
- `it`: systems, integrations, databases, environments, repositories, CI/CD pipelines/runs, releases, technical debts, monitors, incidents, security findings, backups/runs, restore tests, DR plans; permissions `it.read`, `it.write`, `it.delete`.
- `genesis`: agent skills/models/tools, UAT gates/results, technical decisions; permissions `genesis.read`, `genesis.write`, `genesis.delete`.

`navigation_groups` and `navigation_items` are global catalog records and require an active `IT_ADMIN` membership with `identity.accounts.manage`. Workspace-specific visibility uses `/api/v1/workspace-navigation` and requires `navigation.read` or `navigation.manage`.

Shared work records are linked to the creating workspace. Deleting a shared record removes only that workspace's link; it does not delete the organization-level record visible to other workspaces.

## Strategy

Migration `0022` is served by its lifecycle-aware API at `/api/v1/strategy`. Plans, objectives, targets, observations, relationships, assumptions, cascade operations, and revisions must use that API; they are intentionally not exposed by generic CRUD because they have versioning and approval/activation rules.
